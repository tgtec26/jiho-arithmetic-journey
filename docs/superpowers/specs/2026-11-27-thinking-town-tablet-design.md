# 생각 마을 (태블릿 사고력 활동) 설계

작성일: 2026-11-27 · 웹앱 "지호의 산수 여행"에 더하는 새 활동. 인쇄용 생각 퍼즐 학습지(`2026-11-27-thinking-worksheet-design.md`)와 퍼즐 규칙을 나눠 쓴다.

## 1. 의도

- 지금 앱의 게임 14개는 거의 모두 "그림 보고 4개 중 하나 누르기"인 단순 합산·셈이다.
- 아빠는 이제 **가벼운 이야기 + 손으로 조작하기 + 추론**이 있는 활동을 원한다. 화면도 평평한 카드가 아니라 **공간감 있는 곳에서 게임처럼** 움직이길 원한다.
- 지호(만 6세)는 계산은 앞서 있지만 공간·논리는 또래 수준. 학습지와 같은 사고력 퍼즐을 태블릿에서는 직접 만지고 결과를 바로 보며 푼다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 홈 화면이 탁자 위 마을 디오라마인 "생각 마을". 장소 6곳, 장소마다 조작으로 푸는 퍼즐 활동 하나.
- 모든 퍼즐은 코드가 만들고 코드가 검사한다(답이 꼭 있고, 정답 판정이 정확함). 학습지와 같은 생성기·검사 코드를 쓴다.
- 아빠와 함께 하는 흐름: 짧은 이야기를 아빠가 읽고, 다 풀면 "어떻게 알았어?" 대화 카드.
- 하나씩 끝낼 때마다 마을이 살아나는 진행(수집·성장의 재미).

**비목표**: 혼자 하기용 음성 읽어 주기·자동 난이도 조절, 서버·계정, 손가락으로 자유롭게 돌리는 3D 카메라(쌓기나무의 90° 돌려 보기만), 다른 아이용 일반화.

**반목표**
- 4지선다를 반복하는 단순 클릭 구조 / 판단 없이 버튼 하나로 끝나는 과제.
- 답이 없거나 여러 개인데 하나만 정답 처리하는 퍼즐.
- 탭 S6에서 버벅임, 스크롤이 생기거나 아래가 잘림(세로 780px).
- 글로 가르치는 화면(설명은 조작 뒤 한 줄) / 밋밋한 성공 연출.
- 실제 아이 사진을 외부 생성 서비스에 보냄.

## 3. 지킬 것 (기존 앱 규칙)

- 갤럭시탭 S6 가로 1280 × 800, 세로 가용 780px 안, PWA 전체 화면, 스크롤 없음.
- Svelte 5(runes), Tailwind 4, 기존 `gameStore` 점수·기록과 이어짐, 카드는 스쿼클, 터치 대상 넉넉히.
- 등장인물: 지호·아빠·감돌이(곰)·사랑이(고양이)·손님 — 학습지 스티커 PNG를 그대로 씀.
- 음향: `snug-game-principles` CLAUDE.md 7절(찾기 우선 → 공통 세트 → 생성은 마지막, 첫 입력에서 오디오 풀기, 음소거 유지, 연타 간격 제한, 사용자가 들어 보고 확정).
- 커밋 계정 `tgtec26`, 푸시는 테스트 + 탭 크기 브라우저에서 눈으로 확인 뒤(전역 CLAUDE.md 규칙. 저장소의 GEMINI.md "컨펌 후 배포"보다 새 규칙이 우선).

## 4. 사용자가 정한 것

- **주로 아빠랑 같이** 한다 → 음성·자동 힌트는 가볍게, 아빠가 읽고 묻는 흐름.
- 공간감: **A. 장난감 디오라마** — 탁자 위 장난감 판을 비스듬히 내려다보는 고정 시점, 차·블록은 입체 상자, 인물은 세워 둔 종이 인형.
- 구성: **생각 마을 6장소**와 한 번 할 때의 흐름(아래 5·6절) 그대로 승인.

## 5. 화면 흐름

1. 산수 여행 메뉴에 "생각 마을" 칸 하나 추가.
2. **마을 지도**: 디오라마 마을 판, 장소 6곳(이름표), 지금 할 곳이 통통 튐, 끝낸 곳은 살아난 모습. 위쪽 알약: 마을 도장 수, 별.
3. **장소 들어가기 → 3컷 이야기**: 디오라마 위에 인물 종이 인형 + 말풍선, 아빠가 읽고 넘김.
4. **퍼즐 3~5판**: 점점 어렵게. 판마다 성공 연출(팝·반짝임·소리).
5. **대화 카드**: "어떻게 알았어?" + 활동별 질문 하나. 아빠가 지호 설명을 듣고 ⭐ 버튼을 누르면 별 하나 더.
6. **도장 + 장소가 살아나는 연출**(3~5초 피날레) → 마을 지도로.

## 6. 장소별 활동

| 장소 | 활동 | 조작 | 추론 포인트 | 퍼즐 코드 |
|---|---|---|---|---|
| 🚗 주차장 | 주차장 탈출 | 차 상자를 끌어 축 방향으로만 밀기(막히면 멈춤) | 어떤 차를 먼저 비켜야 하나 | 학습지 `parking.js` |
| 🧱 블록 공방 | 쌓기나무 | 바닥 칸을 눌러 블록 쌓기·빼기, 90°씩 돌려 보기 | 설계도(위·앞·옆 모양)에 맞는 탑 | `blocks.js` 보이는 모양 |
| 👕 옷가게 | 경우의 수 | 마네킹에 옷 입히고 사진 찍기 → 사진첩 채우기 | 빠짐없이·겹치지 않게 | `counting.js` |
| 🎫 기차역 매표소 | 줄 세우기 | 인물 종이 인형을 줄 칸에 끌어 세우기 | 단서 카드를 모두 만족하는 순서 | `logic.js` 줄 세우기 |
| 🌼 사랑이 정원 | 모양 스도쿠 | 꽃 4종을 4×4 화단에 심기 | 줄·네모마다 하나씩 | `logic.js` 스도쿠 |
| ⚖️ 시소 놀이터 | 무게 추론 (태블릿 전용) | 인형 둘을 시소에 올려 기울기 보기 | 적은 횟수로 가장 무거운 인형·순서 찾기 | 새 `seesaw.js` |

### 6.1 주차장
- 6×6 디오라마 판, 빨간 차를 오른쪽 출구로. 움직임 수 세기와 "가장 적게 N번" 목표, 되돌리기·처음부터.
- 단계 1~5: 가장 적은 횟수 범위를 학습지 라운드 범위처럼 늘림.
- 성공: 빨간 차가 출구로 달려 나감.

### 6.2 블록 공방
- 단계 1·2: 위에서 본 모양에 칸마다 층수가 적힌 설계도 → 그대로 쌓기(답 하나).
- 단계 3~5: 위·앞·옆 모양 설계도 → 세 모양을 모두 만족하면 정답(답이 여러 개일 수 있어 판정은 보이는 모양 비교로). 도전: "가장 적은 블록으로".
- 90° 돌려 보기 버튼(4방향 고정 시점). 자유 회전은 하지 않음.

### 6.3 옷가게
- 셔츠 m벌 × 바지 n벌(뒤 단계는 모자까지 또는 아이스크림 맛 고르기·기차 칸 순서). 마네킹은 단순한 옷 모양으로(지호 그림에 옷을 겹치지 않음).
- 입힌 조합을 사진 찍으면 사진첩 칸에 들어감. 이미 찍은 조합이면 흔들림 + "이미 있어". 칸을 다 채우면 성공.
- 앞 단계는 사진첩 칸 수 = 답, 뒤 단계는 칸 수를 숨기고 "다 찾았다" 버튼(틀리면 남은 수 힌트).

### 6.4 기차역 매표소
- 단서 카드 2~5장(학습지 문장 그대로), 줄 칸에 인물 끌어 세우기, "확인"을 누르면 단서 카드마다 맞음/틀림 불이 켜짐(어느 단서가 어긋났는지 보임).

### 6.5 사랑이 정원
- 꽃 4종(모양·색), 같은 줄·네모에 겹치면 그 꽃이 빨갛게 흔들림. 다 심으면 꽃이 핌.

### 6.6 시소 놀이터 (새 활동)
- 인형 3~5개의 숨은 무게. 둘을 시소 양쪽에 올리면 무거운 쪽으로 기움. 잰 횟수 표시.
- 단계: 3개 중 가장 무거운 것(2번 안에) → 4개 중 가장 무거운 것(3번) → 3개 순서 → 4개 순서(5번) 등. 정해진 횟수 안에 시상대에 올리면 성공.
- `seesaw.js`: 지금까지 잰 결과와 맞는 무게 순서를 모두 추적해 답이 확정됐는지 판정, 단계별 최대 횟수.
- 찍어서 맞히기 금지 (Claude가 정함: 추론을 연습하는 활동이라서). 시상대는 잰 결과로 답이 **확정됐을 때만** 받는다. 확정 전에 올리면 시소가 흔들리며 "아직 확실하지 않아" → 더 재 보게 함.
- 숨은 무게는 처음에 정하지 않고, 잴 때마다 아직 가능한 순서 중 답이 가장 늦게 정해지는 쪽으로 결과를 고른다(운으로 일찍 끝나지 않게).
- 최대 횟수를 넘겨도 끝까지 풀 수 있고, 횟수 안에 풀면 별 하나 더.

## 7. 진행·보상

- 장소마다 단계 5개. 한 번 들어가면 현재 단계 퍼즐 3~5판. 단계를 끝내면 도장.
- 장소는 자유롭게 골라 들어감. 통통 튀는 곳은 "다음에 해 볼 곳" 추천일 뿐. (Claude가 정함)
- 장소가 살아나는 모습은 두 번(Claude가 정함: 처음부터 바로 변화가 보이게, 그림 수는 12장면으로 억제): 1단계를 끝내면 기본 움직임(주차장에 차가 다님, 공방 굴뚝 연기, 옷가게 진열장, 기차가 지나감, 꽃이 핌, 시소에 아이들), 5단계를 끝내면 장식이 더해진 완성 모습 + 깃발.
- 5단계를 다 끝낸 장소는 가장 어려운 단계의 새 퍼즐로 계속 할 수 있음(별은 계속 쌓임).
- 아직 만들지 않은 장소(13절 순서상 뒤 단계)는 지도에 "공사 중" 울타리로 보임.
- 별은 생각 마을 전용 누적 수로 따로 저장(기존 `gameStore.score`는 "기록 남기기"에서 0이 되므로). 기록 남기기에는 그날 얻은 별을 더함.
- 판 통과 = 풀기만 하면 통과, 가장 적게 풀면(주차장 최소 횟수, 시소 횟수 안, 블록 최소 개수) 별 하나 더.
- 진행은 기기에 저장(localStorage, 기존 store 방식), 별은 기존 점수·기록에도 더함.

## 8. 아빠와 함께

- 대화 카드 질문 예: 주차장 "어떤 차를 먼저 비켰어? 왜?", 블록 "옆에서 보면 몇 층이 보여?", 옷가게 "빠뜨리지 않으려고 어떻게 했어?", 매표소 "어느 단서부터 봤어?", 정원 "이 칸은 왜 이 꽃이야?", 시소 "왜 이 둘을 먼저 쟀어?".
- 아빠 버튼(힌트·⭐)은 길게 눌러야 동작(지호가 실수로 누르지 않게, Claude가 정함).
- 힌트 버튼(아빠가 누름) 한 단계: 주차장 첫 움직임 반짝, 블록 한 칸 보여 주기, 매표소 단서 하나 강조, 정원 한 칸 채우기 등.

## 9. 이야기

- 장소마다 단계별 3컷 이야기 5개(총 30개), 학습지와 같은 말투·등장인물. 말풍선은 짧게(아빠가 읽음).

## 10. 디오라마 그림 규칙

- 고정 시점(판을 앞으로 약 58° 눕히고 약 35° 돌림), 상자 면은 한 색의 세 밝기, 판 둘레는 나무 테두리, 하늘·잔디 배경.
- 인물은 스티커를 세운 종이 인형 + 바닥 그림자. 장식 건물 그림은 Codex로 같은 그림체.
- 화면 글자는 적게, 피드백은 움직임·소리·색으로. 성공은 길고 화려하게(팝·파티클·별 카운트), 실패는 짧게(흔들림 + 소리).

## 11. 만드는 방법 (Approaches)

- **A. CSS 입체 + 지금 앱에 더함 (선택)**: CSS 3D 상자·SVG·스티커 종이 인형, 새 의존성 없음, 탭 S6에서 가벼움, 한글 선명, 끌기 쉬움, 학습지 퍼즐 코드 재사용. 진짜 빛·그림자는 없음(면 밝기로 흉내).
- B. WebGL(Three.js) 고정 카메라: 진짜 빛·그림자, 앱 크기 증가, 누른 대상 계산·한글 겹치기로 품이 두세 배 → 뺌.
- C. 미리 그린 입체 그림: 퍼즐마다 모양이 달라 그림이 끝없이 필요 → 뺌.
- 사용자가 결과물 이야기를 했고 만드는 방법은 빌더(Claude)에게 맡김. A로 정함.

## 12. 구조

- 퍼즐 규칙: `worksheets/lib/think/`의 순수 모듈(`common.js`, `parking.js`, `blocks.js`, `counting.js`, `logic.js`)을 앱에서 그대로 가져다 씀(Vite 별칭). Node 전용 모듈(`episode.js` 등)은 가져오지 않음. 새 `seesaw.js`도 같은 곳에.
- 앱: `src/lib/think-town/` — 디오라마 부품(상자·판·종이 인형), 마을 지도, 이야기 띠, 대화 카드, 장소 6개 컴포넌트, 진행 store.
- 메뉴에 `GameMode` 하나 추가.
- 퍼즐은 미리 만들어 JSON으로 앱에 넣음(주차장 생성은 탭 S6에서 실시간으로 돌리기에 무거움). 학습지에 나온 퍼즐과 겹치지 않게. 경우의 수는 학습지에 생성기가 없어 옷가게용 작은 생성기를 새로 둠(셔츠 × 바지 × 모자처럼 세 목록도 지원).
- 스티커 PNG는 앱용으로 작게 줄인 사본을 씀.
- 테스트: 순수 규칙은 vitest, 조작(끌기·정답 판정)은 컴포넌트 테스트 몇 개 + 탭 크기 브라우저 확인.

## 13. 만드는 순서 (단계마다 쓸 수 있는 상태로 배포)

1. 마을 지도 + 디오라마 부품 + 주차장 + 기차역 매표소 (조작이 가장 다른 둘).
2. 블록 공방 + 사랑이 정원.
3. 옷가게 + 시소 놀이터 + 마을 살아나는 연출 전부.
